# 设计报告与证据模板

## 先收集

读者/用途、指南/模板版本、用户最新稿、器件/工具、系统输入输出、实际 RTL/HLS/软件结构、接口合同、基线与验证证据。通用 FPGA 工程不要求存在处理器或特定应用；竞赛条款按实际赛道核对。

## 沿用户框架组织

介绍解决的问题和约束；用可读的系统框图交代模块及数据方向；解释并行/分时、位宽、存储和握手等有依据的架构选择；用资源/性能/数值验证支撑；给出从源到产物的复现入口。已有章节能表达时不新增重复栏目。

职责写到实际执行位置：RTL/HLS 负责哪些实时计算/控制，处理器负责哪些调度/配置/交互，主机负责哪些离线工作，板级电路负责哪些接口。接口写明数据/控制内容、频率或触发、位宽/协议、同步及异常行为。

量化段落：

> 在【器件、工具、时钟、负载、实现阶段】下，相对【冻结基线】，【候选】的【资源/吞吐/时延/误差】由【前值】变为【后值】。通过【参考、RTL、网表、集成或实板方法】验证【范围】。结果覆盖【次数/数据/条件】，复现入口为【命令与证据】。

静态时序、仿真周期、核吞吐、软件调度、板端端到端时延分开；WNS 不是测速、窗口数不是独立样本、算法意图不是功能实现证明。收益应有同条件基线，器件剩余资源不只看 LUT，还看布局和时序瓶颈。

报告正文面向评委或评审，内部文件代号留证据索引。失败经验用“问题—选择—验证—结果”简洁呈现。突出已证实优势，同时在方法/范围中保留必要限定，不承诺未测性能。

## 复用与协作

案例记录场景、输入、真实观察、变更、测试、结果与失效条件。原始可见交互与整理摘要分开，无原文不生成假历史。具体竞赛的目录、评分、PYNQ 鼓励项不写成所有 FPGA 工程规则。

历史来源：[AMD 指南与报告案例](case-report-evidence.md)。该来源支持方法和事实核对，不证明评分或获奖效果。
