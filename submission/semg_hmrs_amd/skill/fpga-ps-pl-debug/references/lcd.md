# 显示、缓存与主循环调度

适用于含 framebuffer、DMA 扫描和处理器交互的系统；无显示则无需使用本节。

先明确分辨率、像素格式/步长、缓冲数、DMA 扫描索引、绘制缓冲和 cache 操作。撕裂看缓冲所有权及切换时点；颜色/散点看数据格式、字模步长/位序、前景背景、裁剪和字号基线。真实固件可 host 渲染时复用同一绘制代码，避免另做一个好看的模拟页面掩盖原缺陷。

频谱/波形显示核对线性/对数、幅度/功率、bin 映射、DC、标度、自动量程及顶部余量。区分数据饱和和绘制冲顶；不能直接压平高柱伪装修复。测试零值、DC、小幅/满幅和已知峰值。

全页和触摸一起变慢时，测采集积压、后台任务、存储、渲染和中断负载。将可拆任务分块续算，块间服务关键路径，并以实际目标计时器扣额度。单块可超预算时不能称硬实时上限；同时检查后台结果更新新鲜度，不能让其饥饿。

状态 ACK 与可见内容变化分开，避免每次 ACK 都触发重绘。分别测面板扫描频率、内容切换率、绘制耗时和触摸/端到端响应；静态页面内容 FPS 为 0 并不代表面板停止。host 耗时不代表处理器耗时。

修改后检查真实像素、全帧/增量一致性、输入按下/释放、边界/分辨率、计时器回绕及无效状态。任务块大小改变时固定调用次数不再代表相同计算量，吞吐测试要保持工作量可比；不要删掉失败断言。

来源：[显示与调度案例](case-ui-scheduling.md)。案例已验证软件行为，不声称实板 FPS 提升。
