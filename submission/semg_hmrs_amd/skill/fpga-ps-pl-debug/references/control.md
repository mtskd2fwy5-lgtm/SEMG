# 寄存器、快照与输出状态

## 输入与观测

列出命令/响应端点、位宽/字节序、地址、时钟/复位、代次或 toggle/ACK、超时/故障、有效位与状态机。按“数据就绪→决策→目标→命令接受→输出→外部反馈”分别取证，不把界面显示正常推导成输出已使能。

多字结果用冻结快照/版本检查等实际协议保证一致性，不能逐地址读取正在变化的矩阵后拼帧。命令 payload 的保持时长、跨域捕获、ACK、重试/取消语义要完整。频率成整数倍不证明 CDC 安全；逐位同步也不能保证多位总线原子一致。

DMA/共享内存检查生产者与消费者所有权、对齐、cache clean/invalidate、内存屏障及映射属性。根据真实平台 API/缓存行和一致性能力处理，不机械添加 flush。

## 典型状态问题

- 复位完成与自动跟随是不同模式；查是否需要显式使能、配置完整、数据新鲜和租约续期。不要自动绕过保护修复“没动”。
- 多路目标需同帧生效时先暂存，验证完整性后原子提交；STOP/复位/配置变更清除半包。通道数和帧长来自实际协议。
- 持续保持、停止信号、失电和物理卸力是不同概念；没有反馈只能确认命令/波形。不同设备停信号后的行为需实测。
- 配置/模型加载采用先校验后替换；版本、长度、校验、范围和关闭失败都应处理，旧实时状态不能混入新配置。
- 逻辑信号、板级电平转换和外设极性分层核对；内部正逻辑与引脚有效电平分开。测试测量脉宽而非只看是否翻转。

## 验证

用实际生产驱动/mock MMIO 或 RTL 自检覆盖正常、超时、重复、断流、复位、回绕和切换。软件金模型与硬件失败不得静默互换。CDC 需协议和物理约束/报告共同检查，行为仿真不证明亚稳态概率。

案例：[多轴复位/使能/极性](case-atomic-control.md)。这是 PWM 外设实例，不要求其他工程沿用相同模式或保护阈值。
