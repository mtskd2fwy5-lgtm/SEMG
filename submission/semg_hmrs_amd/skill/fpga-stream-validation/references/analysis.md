# 流式验证：从源到文件

## 输入模板

实际链路、时钟/采样率、数据/序号位宽、通道与打包顺序、字节序、标度/增益、帧头尾、序号递增规则、复位行为、FIFO 深度、DMA 大小、缓存所有权、运行版本。标注来自人工还是模型、数据来自哪一级，都应显式记录。没有相关模块时省略，不假定必须有 ADC、DMA 或标签。

## 排查顺序

先查帧结构及序号，再判断波形。正常回绕、前跳、重复与倒退分开；半圈以上跳变可能有歧义。若前一缓冲内容原样重现，记录重复长度并与 FIFO/DMA 块长比较，检查复位是否仅作用于读侧，以及缓冲是否在消费前重用。不得用取模差值把倒退解释为巨大丢帧。

按测试点比较源计数→跨域→DMA→解析→文件。输入序列持续变化可区分“接收到旧数据”和“源本身不更新”。故障复位丢失的数据无法靠后处理恢复，保留错误/排除区间。

处理级合同写清：输入、采样率、缩放、符号、滤波/抽取、延迟、是否整流、输出位宽。raw、最终 signed 数据、包络和特征不同；同名出口升级也需元数据/协议标识。避免已处理数据再走同一滤波链。

采用冲激/阶跃/正负满幅/零尾、通道独立计数、随机背压与复位等已有测试进行比对。报告削顶、平线、偏置和频域时写明数据级、单位、带宽与窗口；谱能量比例下降可能只是分母变大，结合绝对量解释。物理模拟问题不能仅靠数字输出认定原因。

## 独立 CSV 工具

新建 capture.csv：

```csv
seq,value0,value1
65535,-5,3
0,8,-2
2,4,1
```

```text
python scripts/audit_stream.py capture.csv --signal-columns value0,value1 --sequence-column seq --counter-bits 16 --output audit.json
```

应输出回绕 1 次、前向缺号 1 个，以及 SHA256、行数、异常前 50 条、每列极值/均值/去直流 RMS。只需 Python 标准库，源文件只读，输出路径已存在则拒绝。事件 row 是从 0 开始的数据行号；不是 CSV 含表头的行号。

表头唯一，序号为声明位宽内无符号整数，数值为整数。可用 `--signed-rail-limit 8388608` 指定 signed24 边界；应按当前数据级真实范围设置，未指定为 null。触轨计数包含到达或超出边界的值，不证明模拟链是否线性。不接收浮点单位列，不猜采样时间或标签。整数计数以外格式需使用对应解析器，不为迁就脚本损失精度。

来源：[具体采集案例](case-stream-replay.md)。脚本覆盖有限序号歧义；不能单靠它区分设备重启与真实倒退。
