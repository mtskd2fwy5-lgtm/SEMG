六、策略提示与需要修正的细节
主线要压在初级组得分点：逻辑设计、状态机、时序约束、接口协议。报告把 ADS1299 的 SDATAC/WREG/RDATAC 状态机、AXIS 跨时钟域、clock_groups 约束、SPI/AXI-DMA 协议作为技术主线；PS 裸机定位为“配置与传输引擎”，不抢戏。
三个可写死的创新点：① 采集→滤波→特征→INT8 推理→疲劳→重建反馈的单芯片确定性闭环，且全链路与 Python 金模型逐位可验证；② 低成本 8 通道 sEMG 边缘方案，推理占空 <0.2%、资源余量充足；③ 自写 2048 点 radix-2 FFT（规避 Xilinx IP 授权/可移植）+ 16-MAC 时分复用 INT8 引擎。
避免失分：
  • 44 类双头 CNN（acc 61.6%、R² 全为 NaN）是失败/探索路线，不要放进主成果，最多在“失败分析/未来工作”一句带过，否则现场易被质询。
  • src/rtl/hand_motion_top.v 是孤立旧顶层，实际综合走 Block Design(emg_pl_export)；建议删除或在注释/README 标明，避免复现混淆。
  • 指标口径需对齐：README 主张 LoSo 84.9%，而 data/metrics/baseline.json 写 pooled 84.04%（S3 65.1%），int8_validation 为 67.4%；提交前统一为最终功能选位模型口径并归档。
  • PYNQ 是“推荐/加分”非必选。裸机链路已验证，不建议 10 月重构架构；若进度富余，只加一层薄 PYNQ（同一 Overlay + Python 读 DMA/虚拟手）冲通用 skill 加分。
  • PC 3D 虚拟手仅保留为调试和造型检查；最终演示以 PS 本地 LCD 为准，仍需补真实输入、显示和 QSPI 自启动实测。
本看板为工程就绪度诊断，分数项为基于现有证据的人工预估；所有硬指标均可在 build/vivado/.../impl_1 报告、sim/results、data/metrics 中复核。
