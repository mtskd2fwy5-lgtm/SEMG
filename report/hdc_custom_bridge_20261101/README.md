# HDC 自定义手势联动修复与稳定条件放宽（V28）

- BOOT：`build/boot/BOOT_20261101_HAND_CONTROL_HDC_DYNAMIC_CUSTOM_BRIDGE_V28.BIN`
- 基线：V27（`report/hdc_custom_only_20261101`，哈希绑定见 `baseline/manifest.json`）
- 日期：2026-11-01

## 缺陷（上板复现）

V27 上板后手控页一直显示"等待稳定 HDC 手势"。根因：板上默认从 **1 个**自定义手势
起步，而 PL 学习加速器对单类模型（`arg[4]==1`）固定返回 margin=0（emg_learning_accel.v
state 85），稳定判定的合格证据要求 margin>=2%，因此永远无法累计有效票。V27 之前
最少 6 类（5 基本手势），单类分支从不触发；V27 去掉固定基本手势后正好踩中。

单类模型本质上也没有对手类，无法区分"目标动作"与"静息"（任何窗口都会预测唯一类），
直接放行会导致手在静息时也一直保持在目标姿态。

## 修复（PS 侧，PL 不变）

### 单类库显式拒绝（lcd_hdc.h / lcd_hand.h）

- `hdc_hand_model_ready()` 要求 **>=2 个**已验证自定义手势才允许手控/虚拟联动。
- 手控页状态区分显示："仅1类手势 / 至少2类才能联动"（不再是无提示的"等待稳定手势"）。
- 学习页在 DONE 且仅 1 类时提示"先新增1个手势 / 至少2类才能联动"。
- 使用建议：第 1 个自定义手势采集**放松/静息**状态作为基准，第 2 个起采集目标动作
  （相当于把原固定"放松"类交给用户自定义）。

### 稳定条件放宽（hand_control.h / lcd_hdc.h）

| 项目 | V27 | V28 |
|---|---|---|
| 合格分数间隔 | >=2% | **>=1%** |
| 投票规则 | 最近 5 窗取 3 | **最近 6 窗取 3** |
| 保持失效 | 8 窗 / 200ms | **10 窗 / 250ms** |
| 类 0（原放松遗留） | 8 窗取 6 | **与所有类一致（3/6）** |

振荡抑制不变：仍需领先对手 2 票或 3 个连续强预测，3:3 交替永不确认。
