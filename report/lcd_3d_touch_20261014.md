# 左手第一视角 3D 与 GT911 触摸修复

日期：2026-10-14。固件标识：`20261014_LCD_3D_GT911`。

后续版本已改为默认掌心朝上，修正全局抬臂方向并优化动作后误差。当前实现与镜像请以 [lcd_palm_imu_20261014.md](lcd_palm_imu_20261014.md) 为准；本报告保留前一版验证记录。

用户确认：ATK-4384（800×480）；左手；MPU 固定前臂，X 朝小指侧、Y 朝手肘。镜头固定为本人眼睛向手看的方向，前臂从下方伸入，手掌、手背和侧面随旋转变化。本报告取代同日较早的 `lcd_optimization_20261014.md` 中关于二维显示、安装轴未确认和旧镜像散列的描述。

代码、主机回归、引脚级 I²C 仿真、完整 Vivado 构建及本地启动镜像均已完成。尚未下载到板卡或写入 SD 卡；未测得实机帧率、输入延迟或触摸效果。读取 COM16 被拒绝，可能被现有串口程序占用，没有关闭该程序或向板卡发送命令。

## 触摸根因与修复

GT911 的状态地址为 `0x814E`，第一触点从 `0x814F` 开始：

| 地址 | 内容 |
|---|---|
| 0x814F | 触点 ID |
| 0x8150 / 0x8151 | X 低字节 / 高字节 |
| 0x8152 / 0x8153 | Y 低字节 / 高字节 |
| 0x8154 / 0x8155 | 触点大小 |

旧实现从 `0x8150` 开始读取，却仍按 ID、X、Y 解码，导致坐标错位并可能越界，被 PS 拒绝，因此按键没有触发。此前测试模型沿用了同一错误，未能暴露它。此次按 [Linux 官方 Goodix 驱动](https://github.com/torvalds/linux/blob/master/drivers/input/touchscreen/goodix.c) 的八字节触点布局交叉核对，修正 RTL 的读取起点为 `0x814F`。参考函数为 `goodix_ts_report_touch_8b`；输入报告头后紧接触点数据。

测试模型独立写死真实寄存器地址，使用非零 ID=3、触点大小=7，并检查 `(799,479)`，避免再次让测试与实现共享错误。保留状态触点数驱动的按下/松开、清除 ready、掉线恢复及菜单动作。

界面新增 `TOUCH LINK` / `TOUCH WAIT`。LINK 仅表示前端链路有效，不能单独证明按键已生效。在监测模式、115200-8N1 下发送小写 `t`，即使调试输出关闭，也会打印：

```text
[TOUCH] word=0x... link=... down=... badxy=...
[TOUCH] x=... y=... press=... rel=...
```

`badxy` 统计不同越界报文；正常触摸仍输出 `C x=... y=... dn=...`。记录模式保持原有 2 Mbaud 二进制格式，不插入这些诊断文本。

## 前臂姿态与三维渲染

沿用现有 PL MPU6050 I²C 采样前端，增加每个已接受样本的六轴原始快照，经 AXI GPIO 送到 PS：

| PS 地址 | 高 16 位 | 低 16 位 |
|---|---|---|
| 0x41220000 | 原有有效位、序号和 pitch/roll 打包字 | 同左 |
| 0x41220008 | ax | ay |
| 0x41230000 | az | gx |
| 0x41230008 | gy | gz |

新通道在同一传感器样本发布时更新；PS 用序号字前后读一致性检查保护快照。原有 GPIO 地址及文本姿态接口保留。`mpu6050_motion.v` 是复用原前端的薄包装，避免 Vivado 对旧 module reference 端口边界的缓存。

PS 使用四元数积分三轴陀螺仪，以加速度重力方向作比例校正；明显偏离 1g 时暂停重力校正。100 个不同样本用于零位和陀螺偏置采集；长采样缺口跳过积分。安装方向按左手 X→小指、Y→肘，以 `B=diag(-1,-1,+1)` 转换到前臂基底。每帧固定一份姿态矩阵，避免绘制途中输入改变而使手掌与手指错位。

渲染复用 `tools/virtual_hand.py` 的手掌轮廓和骨长，以及现有 `pose_contract.h` 的 22 维姿态模板。三维体积包含前臂、手掌、各指骨节与拇指；手腕绕腕关节变换，完整前臂和手绕肘锚点旋转。固定眼位相机使用透视投影与逐像素深度缓冲，翻掌时自然改变可见面和前后遮挡。

姿态类别切换保留共享的 220 ms 插值；前臂方向使用最新四元数矩阵。深度以逆深度表示，逐行计算 Q12 步进，再用像素加法插值，避免 Cortex-A9 在每个像素执行软件整数除法。低多边形外观仍有分面感，不是写实皮肤模型。

沿用三帧缓冲所有权保护、绘制中不重启、输入合并、分片渲染和提交前缓存清理。深度清理也分片执行。APP / framebuffer 使用 L1 缓存，肌电 DMA 区保持非缓存；真实缓存与 VDMA 行为仍需上板确认。

## 使用与测量范围

1. 上电后让左前臂朝前，手背朝自己，保持静止约 1 秒建立显示零位；需要重采时点击菜单“MPU校准”，或在监测串口发送 `z`。之后翻掌和三轴转动会改变三维方向，不固定显示手背。
2. 单个前臂 MPU 可估计前臂方向；当前肘锚点和臂长是模型约束，无法从它可靠测出自由肘部位移、肩部运动或手的绝对空间位置。没有进行加速度二次积分来伪造位置。
3. MPU6050 无磁力计，绕重力方向的航向会漂移，需按实际情况重新校零。快速动作期间的线加速度、采样遗漏和陀螺偏置仍会影响方向。
4. 手指和腕关节角度来自原有肌电分类的姿态模板及插值，尚不是逐关节连续实测的 22 自由度重建。
5. 上板后先确认 `TOUCH LINK`，点击菜单和底部姿态键，检查松开后可再次点击。若无效，记录 `t` 的两行输出及按压时是否有 C 行，再区分链路、坐标与界面命中问题。
6. 核对前臂抬起、横摆和翻掌的方向，并持续运动检查撕裂、卡顿；发送 `d` 查看 LCD 完成/合并/溢出计数及肌电序列连续性。实机刷新率和端到端延迟仍需测量。

保留任务开始前已有的 BD / VDMA / video-out 修改和 SOF repair 删除，没有提交或覆盖用户的其他工作。
