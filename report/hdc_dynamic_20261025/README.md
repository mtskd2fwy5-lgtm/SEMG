# HDC 可追加手势与可选机械手映射

候选版本：`20261025_HAND_CONTROL_HDC_DYNAMIC_V7`。基于当前 V6 追加，保留疲劳、康复训练、信号处理和 MPU 旋转路径。完整编译与 BOOT 验收结果见本目录日志及 artifacts.json；不自动写入启动卡。

已生成 `build/boot/BOOT_20261025_HAND_CONTROL_HDC_DYNAMIC_V7.BIN`，5,057,684 字节。全量综合、布局布线及四项硬件验收通过，WNS +0.441 ns、WHS +0.036 ns，时序失败端点均为 0。BOOT 内完整 bitstream 及两个应用加载段均与本轮输入匹配；新增 64 MiB DDR 预留为 NOLOAD，不增加等量 BOOT 文件体积。使用时复制到启动卡并命名为 `BOOT.BIN`，本轮未操作实板。

placed 资源：LUT 40,614（76.34%）、FF 36,217（34.04%）、Slice 12,936（97.26%）、BRAM 26.5、DSP 105。既有工程警告仍存在；未放宽时钟约束。已核对新综合网表包含 direct HDC 与五指暂存逻辑。

## 操作

1. 设置 → 手势自学习，点“开始 / 清空重学”初始化；点“新增手势”继续增加类别。每页八类，用上一页、下一页切换。
2. 原五类及新增类别各采样三次，另做两次独立验证。不需要连接、标定或映射机械手就能学习及识别。
3. 完成一轮后仍可“新增手势”。既有学习样本保留；新类别采完后重建全部原型，并重新独立验证全部类别，以检查新增类别是否与旧类别混淆。重建期间不启用机械手 HDC 联动。
4. 仅当需要驱动机械手时，完成机构六轴脉宽范围标定，进入动作映射。自定义类别只有完成学习后才出现在映射轮选列表；不要求给所有自定义类别建立映射。
5. 对需要执行的类别，逐指编辑并“记录本轴目标”，五指均在范围内后“确认五指映射”。未记录的目标保持未配置，不自动生成动作。
6. 选 HDC 来源，等待已映射的稳定手势，再显式启用。切到未映射类别时停止输出，识别仍继续；重新启用须手动操作。

“开始 / 清空重学”会清空学习库；追加不会清空旧样本。清空后未学习的自定义类别不出现在机械手映射列表中。

## 实现与边界

- 去除固定三个自定义槽位和八类数组，按实际类别数增长存储。没有另设手势个数上限；可用 DDR 和逐类推理耗时仍是实际边界，不能理解为无限资源。
- 链接脚本预留 0x12000000–0x15FFFFFF，共 64 MiB，两组 32 MiB 交替扩容；与 APP、DMA、LCD 帧缓冲分离。只对 APP、HDC、帧缓冲启用既有内层缓存属性，DMA 仍不缓存。
- 分配失败保留现有库并显示内存不足，不覆盖已有手势。采样、原型、验证矩阵、五指映射一起迁移到新存储。
- HDC 仍由 PS 执行。高编号类别先在 PS 查找对应五指目标，再用原 GPIO5 请求/ACK 邮箱发送五个目标和一次提交，PL 原子更新；类别数不再受原 3 位行号限制。未新增引脚。
- PL opcode 12 暂存轴 1–5，13 要求五轴齐全并原子提交；11 的 value=1 选择直接目标 HDC 模式。保留原 PL 原模型及旧 HDC 协议的模式隔离、脉宽范围检查、独立看门狗。
- MPU 独占轴 0，保持用户确认的左 45°、右 225°、零位约 833 us；腕屈伸仍保持此前五指目标。
- HDC 启用门槛仍为全类完成独立验证、每类至少 80%，以及运行时稳定窗、分数间隔与数据新鲜度检查。这些是工程门槛，不是临床验证结果。
- 学习库及新增映射目前保存在 RAM，掉电需重学。“保存 SD 标定”保留原格式，仅保存机构限值及原三类映射；不代表保存 HDC 库或新增映射。读取 SD 限值后须重新确认自定义映射。
- 中文自定义名称输入不在本轮实现，类别显示“自定义1、2、3、4……”；本轮移除的是数量限制。
- 验证 CSV 改为只保存非零混淆项；沿用原有有界缓冲，结果过大时明确报错，不静默截断。大量类别的实板时延尚需验证，不能从主机测试推导实时容量。
