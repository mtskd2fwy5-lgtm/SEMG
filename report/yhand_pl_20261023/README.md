# Yhand Mini：现有 sEMG-HMRS 的 PL 直控可行性评估

日期：2026-10-23。依据用户提供目录的 Arduino v1.6 源码、开发手册及 OpenC328 原理图；未通电测试、未改工程 RTL、未分配实物引脚。

## 结论

可以由 Zynq PL 产生六路舵机 PWM，替代 Arduino 的脉冲生成与运动插值。舵机本体已有内部位置伺服/功率驱动，不需要为这些三线舵机另外设计裸电机 H 桥；PL 仅提供控制信号，不能承担舵机供电。需要独立的舵机电源/配电及经确认的电平接口。

本项目首选“PL 推理 → PS 现有静息门控/置信度/时序稳定/可用适配 → 目标位置 → PL 六路 PWM”。执行时序由 PL 完成，保留当前已经验证的识别行为。若要求从 ADC 到执行器完全不经过 PS，必须先将 PS 的控制决策逻辑及所需适配能力等价迁入 PL；只截取 MLP argmax 会绕过它们，实物可能比 LCD 更容易误动。

## 与当前肌电模型的匹配

- 当前模型只有放松、张手、握拳、屈腕、伸腕五类。可以可靠设计“稳定动作类别 → 已标定机械手姿态”的映射。
- 张手/握拳可映射五路手指开合；放松应映射经标定的休息姿态，不能简单等同强制张开。
- 屈腕/伸腕不能凭名称直接映射到0号旋转轴；机构未提供对应自由度时应先禁用该物理动作或只在LCD显示。
- 每根手指只有一路屈伸执行自由度，不能逐一复现LCD里的MCP/PIP/DIP及侧摆22个角度。
- 当前分类器不输出每根手指的连续角度。机械手能独立运动五指，不代表现模型能识别并重建五指独立连续运动。
- NMF协同系数不是抓力/指关节角度，不能未经额外标定直接作为力控制量。

## 建议的 PL 执行结构

PS accepted pose / calibrated target table → 原子提交的6目标值及使能/序号/心跳 → 跨时钟握手 → PL限幅/每帧限速 → 帧边界更新PWM → 信号隔离/电平接口 → 六路舵机。

不从 lcd_state_cls 或UI预览手势取控制量；复用真正经过门控的 pose_active_cls 决策，明确区分真实识别、康复示范和LCD预览。PS可更新目标及标定表，PL持续自主生成稳定脉冲。失去新推理窗口时即使PS主循环仍运行也必须判定数据超时，不能用无条件软件心跳掩盖采集失效。

25 MHz现有pl_clk下：20ms=500000周期（19位计数器），1μs=25周期，500–2500μs=12500–62500周期。共享帧计数器+6比较器即可输出控制脉冲；目标只在帧边界切换，避免半帧更新产生异常窄/宽脉冲。可用整数步进实现每帧限速，无需浮点或DSP。

可将脉冲分时发出：最大6×2.5ms=15ms，能放入20ms帧；这不保证消除电源峰值，因为舵机负载与内部驱动仍会并发。

本评估不承诺具体 LUT/FF 数：基础计数/比较很小，但AXI封装、跨域、插值、看门狗及诊断会增加资源。最新2026-10-22报告：36423/53200 LUT（68.46%），32389/106400 FF（30.44%），29.5/140 BRAM（21.07%），92/220 DSP（41.82%），占用12479/13300 Slice（93.83%）。WNS=0.432ns、WHS=0.054ns为现有设计结果。简单PWM可行性高，仍须重新布局布线验证，不能用LUT余量代替布线余量。

## 电气连接和硬件边界

1. 直接PWM时断开原Arduino的六路输出与舵机信号的连接，再由PL控制；不要两个输出并接，也不要误把普通PWM插座接到原理图中的三线总线接口。
2. PL当前I/O按3.3V使用，不能接入5V回送。资料未给专用小舵机的输入高电平阈值，3.3V直连能否稳定识别不能认定；优先用适当的单向缓冲/电平转换，或隔离后在执行端输出兼容电平。
3. 舵机独立供电，按舵机型号/堵转电流预算并设置配电、保险/限流和本地储能；不从FPGA GPIO、开发板3.3V或ADS1299模拟电源取舵机电流。若保留控制板仅做供电分配，逐路确认不会反灌Arduino输出。
4. 本项目人体电极同时连接，舵机回流与开关噪声可能恶化肌电。共地方案需要明确回流路径、避免大电流经过模拟地；如采用隔离PWM，则执行端电源也独立，不能再通过地线/USB跨接隔离边界。增加机械手后，原有PC隔离不能自动覆盖新增接线。
5. 实物每指标定开/合端点、方向、休息位、限速。500–2500μs仅为协议限制，不能直接全量扫到端点，防止连杆顶死、夹伤或舵机过流。
6. 没有力/接触反馈时，适合桌面仿生手同步演示，不足以作为对人体施力的康复执行器闭环。需要实际训练力控时，另加力/电流/角度反馈、机械限位与硬件断电措施。

## 两种替代路径

| 路径 | 接线/代价 | 与“PL直控”的关系 |
|---|---|---|
| 保留Arduino，经PL UART发命令 | 115200串口，6目标合包约92字节，8N1传输约8ms；保留原偏置/插值，但依赖其固件 | PL发指令，Arduino生成PWM，属于间接控制 |
| PS给目标、PL直接输出PWM（推荐） | 六路输出+经确认的电平/电源接口，标定迁到本项目 | PWM和执行保护由PL实现，保留PS成熟识别策略 |
| PL原始分类直接接PWM | 还需移植门控/置信度/时序策略；适配与LCD结果一致性额外验证 | 可做到纯PL链路，但不是当前现成能力 |

原Arduino示例发现实现缺陷：serialEvent.ino 第182行 `for (int i;...)` 的局部循环变量未初始化；第255行用解析字符串索引 `i` 写 `servo_do[i].time1`，而此处应按舵机索引操作，存在越界；单路停止命令还有未校验索引的访问。若选择串口过渡方案，应先修这些问题，而不是把示例固件的“停止”当作已验证的急停。未对用户原资料做改动。

## 后续验证顺序

- 先确认实物确为资料中的五指+旋转轴版本、舵机型号/额定电压、可用PL排针。当前没有指定FPGA球位，须与LCD/ADC/MPU/触摸现用引脚核对后才能给接线表。
- RTL仿真验证20ms帧、目标原子更新、行程/速度限制、复位默认不使能、推理数据超时、PS失联、急停；不得让显示/录制背压阻塞执行保护。
- 综合/实现检查新增控制器资源及全工程时序；硬件先无负载测六路脉宽，再单舵机小范围验证，最后逐路标定组合动作。
- 先不接人体观察电源/动作，再验证佩戴时机械手静止和运动对肌电噪声及误识别的影响。
