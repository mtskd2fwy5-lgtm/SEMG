# HDC 分辨率与实时稳定判决

本次针对三个相似自定义手势、约 1%–2% 分数间隔以及离开验证页后等待稳定动作的问题修改。尚无这三类手势的新录制数据，不能从现有回放推导它们的实板准确率。

## 识别与显示

- 新建学习模型从 16 级改为 32 级量化，向量维数仍为 2048；量化、编码、原型更新、相似度与间隔计算均在 PL，NMF 数值不变。
- 原整百分比会丢失小于 1% 的间隔，现在 PL 额外输出 0.01% 单位的间隔；旧整百分比字段保留。该数值是前两类分离裕量，不是分类概率。
- 强证据（间隔 ≥1%）维持 3/6 窗、领先竞争类至少两票或连续三窗。弱证据（0.25%≤间隔<1%）要求 6/8 窗、至少领先三票。完全同分或小于 0.25% 不作为接受票。
- 学习完成后的识别、主页、虚拟手与 HDC 机械手目标共用稳定类别；独立验证仍使用逐窗原始预测，不用平滑结果美化验证正确率。
- 任何类别独立验证不足 80%、超范围通道超过一路、断流、超时或 PL 错误仍禁止输出。主页显示具体等待原因；验证未通过时仍可计算诊断结果，但不绕过资格检查。
- 学习模型、显示来源和页面切换不会自动开启机械手 PWM。

## 模型与固件兼容

PL 学习 ABI 为 0x13，必须搭配本次位流和应用。新模型以 Q32 合同保存，旧 Q16 模型按其原合同和原 ROM 推理、追加学习，不重解释旧原型。两套 ROM 共 4096×32 bit，原 Q16 内容保持。模型文件布局和原型大小不变。

要比较本次效果，请更新匹配 BOOT 后重新学习；直接加载旧模型只获得更精细的间隔与稳定判决，不会变成 Q32。建议将自然放松也作为一个自定义类别学习，避免只有三个主动手势时强制在它们之间选择。每类采集姿态和力度可有小幅自然变化，独立验证保持分轮进行。

## 验证依据

- 独立 C/NumPy 逐位比较编码、原型、预测、整百分比与 0.01% 间隔；覆盖 Q16/Q32、动态类数和合成相近模式。
- 实际学习 RTL 与综合 OOC 网表使用同一事务合同，覆盖 NMF、尺度更新、Q16/Q32、饱和、同分、单类、零尺度及 AXI 错误/看门狗。最终日志和输入哈希见本目录。
- 实际固件 host 回归包含 0.50% 间隔经六窗确认、学习页/主页切换、同分拒绝、交替歧义、验证失败提示、模型库、过期停止和两种 LCD 分辨率；不是另绘的界面替身。
- 历史五类录制采用独立动作段回放，仅用于算法比较：Q16→Q32 准确率分别为 77.49%→77.75%、95.02%→94.58%、67.34%→74.25%、66.46%→66.46%、79.23%→85.04%。这些数值不代表当前三类手势，不采用训练窗口自测作为结论。

## 时序与发布

首次实现发现新增 `quotient/100` 被综合成单周期 64 位除法，最差裕量为 -4.908 ns。已改用原有顺序除法器；预测增加 65 个 100 MHz 周期，独立 RTL 六类最大 77,263 周期（0.773 ms，模拟 AXI 可变停顿）。该数值不等于实板 ARM 调用时间。未调整时钟、未新增假路径。失败报告保留在 `timing_failed_attempt/`，最终资源和时序以 `comparison.json` 和验收日志为准。

发布必须通过源码继承、当前测试哈希、实际综合网表输入、整机时序、XSA/位流一致、应用/FSBL 全部加载段与 BOOT 分区检查；编译完成不等于板上已验证。

## 最终交付结果

最终整机时序通过：WNS +0.004 ns、WHS +0.052 ns，建立/保持违规端点均为 0。相对匹配的 routed 基线，LUT 27,357→27,537（+180），FF 28,784→28,793（+9），BRAM 49.5→51.5（+2），DSP 53→55（+2），Slice 10,779→10,615。功能精度有变化，不能称为严格等价的资源优化。时序余量较小，后续 RTL 或模型结构变化仍须重新实现验收。

方法学报告保留基线已有的 10 项告警（LUTAR-1、PDRC-190、TIMING-9、TIMING-28、TIMING-37、ULMTCS-1）；本次新增的大建立违例已消除，没有通过删除时序约束或新增 waiver 放行。

BOOT：`build/boot/BOOT_20261102_HAND_CONTROL_HDC_DYNAMIC_RESOLUTION_V29.BIN`。打包已通过原系数绑定/网表/常量/时序门禁、XSA 完整位流一致、应用 2 个 PT_LOAD 与 FSBL 3 个 PT_LOAD 校验。非工程模式 XSA 导出会重新写入 bit 文件时间戳，已确认除头部时间字段外逐字节相同，并将 XSA 内的完整 bit 作为打包输入；详见 `xsa_bit_extraction.json`。

尚未写入用户 SD 卡，也没有宣称完成真实三个新手势的板端验证或机械手物理动作验证。
