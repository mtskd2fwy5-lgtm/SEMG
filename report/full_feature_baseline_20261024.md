# 完整功能追加与优化对比约定

日期：2026-10-24。用户确定开发顺序为先追加完整功能，再优化对比；自定义手势需支持自定义名称和机械手映射。已确认名称直接在LCD用中文拼音键盘输入。本文件冻结交付边界，不表示已实现固件或上板功能。

## 1. 三组版本及比较方式

| 版本 | 定义 | 作用 |
|---|---|---|
| 当前版 | 已有基础PL链与PS HDC/质心验证，资源见同日审计 | 当前功能/资源起点 |
| 完整追加版 | 在原FIFO、特征、滤波组织上补齐PL学习、推理、拒识/稳定、持久化、中文命名和机械手映射/执行 | 测量真实功能增量并保存完整功能基线 |
| 优化版 | 保持完整追加版的功能、算法、模型与输入，改变存储/运算组织 | 测量优化节省和时序/延迟代价 |

先开发新增模块不要求先改原链路。新模块采用正常的BRAM、串行计算和完整协议，不故意用2048维全展开制造资源浪费。算法及原型数量在完整追加基线冻结前确定；HDC和质心仍需独立验证，不按某次验证混淆临时拼接分类器。

每版记录源文件/参数/工具及约束版本、模型与配置摘要、测试集和动作标签、bit/ELF/BOOT及相关SD资源哈希、完整资源/时序报告。保存产物到独立目录；本轮文档变更不自动Git提交或覆盖现有BOOT。

若追加版超资源、无法布通或时序失败，保留失败报告，不能声称具有可上板基线。随后记录必要的最小调整，形成“完整功能可运行基线”；后续优化仍相对此基线比较，同时保留最初失败的追加结果，不跳过失败数据。

## 2. “完整功能”的验收范围

1. 保留基础五类、LCD重建/康复/波形/频谱/质量/协同、SD原始与处理后波形及标签等现有能力。
2. PL接收完整特征窗，完成个体化训练参数建立、编码、原型更新、推理、拒识和稳定决策；PS仅进行标签引导、控制、评分及存储管理。
3. 保留分次学习、独立验证、完整试次提交/取消、当前与候选隔离、冻结验证和显式原子激活；用户可重学、重新验证、保存和恢复模型。
4. 自定义手势可在LCD中文命名，名称用于采样、验证、实时结果与报告；不再只能看到“自定义1/2/3”。
5. 自定义手势可编辑对应的六路机械手目标姿态，保存/恢复并由PL按最终已接受类别查表执行。
6. PL来源选择互斥，模型/映射切换、断流和失效均有确定行为。学习/验证及UI示范不直接驱动物理机械手。
7. 用户当前确认的是每个手势绑定目标姿态。多段动作序列、自动力控、测量逐指连续角度、扩充自定义类别数量不是本次已确认的新增要求。保持当前最多三个自定义槽位，未来扩类单独预算。

完整软件/RTL链验收与实物接线验收分开记录。现有资料未确认每路机构限位和所有可用PL球位，不能自行填数声称机械手已经可直接使用。

## 3. 名称输入及类别语义

- LCD提供拼音输入、候选字选择、删除、确认/取消及英文数字输入；不用PC/网络完成命名。命名页与原采样按钮分开，避免编辑触摸变成开始采样。
- 名称作为UTF-8元数据，设定明确字数/字节上限并提示，禁止截断半个UTF-8字符。空名回退提示或拒绝保存，具体容量由实现时结合布局确定。
- 名称可修改，内部类别标识保持稳定。不得以同名字符串判断类别或执行目标，也不能用不同模型的custom1槽号认定是同一个动作。
- 模型包存储模型标识、类别标识、名称和动作语义；报告保留这些标识与当时名称的快照。单纯重命名不重训、不改变识别编号、不改变机械手映射。
- 现有 `tools/gen_hz_glyphs.py` 从源码收集界面汉字，生成16/20/24/32四种尺寸字形。它不是完整中文字库；中文候选输入需要配套SD词库、字库索引及字形缓存，不能只把输入框改成UTF-8就称为中文输入。
- 新中文资源独立预算版本、字形覆盖、SD读取和PS内存；不把全字库塞进现有4MiB APP区。词库/字体丢失或损坏应明确提示，保留已保存名称和模型，不能静默删字或把名称替换成另一类别。
- LCD输入、模型导入、报告导出均检查编码、长度与CSV转义；若字库不支持某字，应在选字/保存前明确显示，不能保存后才变成无法辨认的散点。

## 4. 可配置机械手映射

数据关系为：`模型标识 + 类别标识 → 执行开关 + 六路目标 + 机构标定版本 + 映射版本`。显示名称与这组关系分开保存。

LCD选择手势后，可修改六路目标、选择不执行、查看当前已保存映射并显式应用。目标面向已标定的五指和0号旋转轴，界面可采用相对开合量；最终查表提交PL的是校验后的脉宽目标。没有已确认标定时，不提供假定有效的满量程姿态。

- 手势和机械手姿态可以不同形，例如“比耶”绑定用户配置的另一目标姿态。不能依手势名称自动推断执行动作。
- PL以新鲜且有效的最终动作查表；PS只管理表和模式，不逐窗把类别转成命令。
- 六路值在一次配置内完整提交，写入候选映射并校验范围、机构配置和类别绑定后原子应用。应答包含版本；编辑中的半组目标不得生效。
- 编辑界面与试动分离。预览默认只显示目标；试动需要单独明确的用户操作及有效机构配置，不能让拖动控件实时触发自动执行。
- 保存内容包含名称、模型、类别、映射和机构标定引用。加载模型时核对绑定，未知或不匹配的配置不得按槽号继承旧物理动作。
- 新类别默认不执行。未配置、未标定、拒识、断流、切换模型及映射失败的行为须在PL执行状态机明确，不能把未知类别当作放松或随便取第0行。
- 沿用PWM原语的目标原子更新、限速、超时与失效检查。0号旋转轴不默认等于屈腕/伸腕；输出状态不是实际到位反馈。

名称和词库主要消耗PS/SD资源；8类×6路×uint16目标仅96字节净载荷，双表192字节，另有标定、使能、版本、校验及协议控制。映射表容量很小，不代表其PL接口/状态机为零成本；资源以综合为准。

## 5. 优化对比与通过条件

完整追加基线通过后，优先改深FIFO为BRAM，再进行特征运算及跨通道滤波复用。顺序来自现有资源实测，见[资源预算](resource_budget_20261024/README.md)。每个优化独立保留结果。

| 对比项 | 要求 |
|---|---|
| 资源 | 同一器件、工具和构建约束下，整机及模块LUT/FF/Slice/BRAM/DSP；分别列追加成本与优化节省 |
| 实现 | 综合、布局布线、WNS/WHS/TNS/THS；失败结果如实保留，不用OOC替代整机通过 |
| 数值行为 | 同一完整输入流逐位比较滤波、特征、编码、分数、训练参数与逐次原型更新；不只看最终准确率 |
| 时间行为 | 窗口/标签边界、配置确认、候选提交、得分有效时刻、稳定判决、PWM帧切换；允许的延迟变化单独列出 |
| 数据完整性 | 相同DMA背压、LCD刷新、SD读写和学习工作负载下的丢窗/overflow、复位与恢复 |
| 功能一致 | 同样的中文命名、模型恢复、映射和机械手行为；字体/词库资源版本一致 |
| 识别质量 | 相同冻结模型、输入与标签；原始预测和稳定输出分开，跨佩戴/动作边界另验 |

将int16改int8、改变维度/原型数量或HDC换质心属于表示或算法变体，应单列比较。若严格计数证明int8与int16在规定域内精确等价，附证明和边界测试后再作为等价压缩项；不能混入普通FIFO/算术复用收益而省略验证。

当前版本与完整追加版功能不同，只能用于说明功能增量；资源优化成效应以“完整追加版对优化版”为主。
