# NMF 与 HDC 计算迁入 PL — V12

日期：2026-10-26。用户所说的“HDL”按此前上下文解释为 HDC 超维计算。
匹配版本：`20261026_HAND_CONTROL_HDC_DYNAMIC_V12`。构建与最终镜像结果见本页后续验收记录。

## 分工与数据路径

| 部分 | PL 运算 | PS 管理与显示 |
|---|---|---|
| NMF | 固定 Q15 基矩阵、八轮乘法更新、三路 Q8 协同系数、百分比、L1 近似残差 | 窗口完整性、反馈平滑、个人舒适参考、趋势与康复任务 |
| HDC | 八通道训练最大值、16 级归一化、2048 维编码、正票并列、带符号原型饱和更新、全类点积、最佳/次佳与间隔值 | 用户标签、3 轮学习/2 轮验证、完整试次提交、DDR 库增长、名称、评分与映射 |
| 执行 | 六路 PWM、限幅/限速、原子复位与持续保持、链路超时保护 | 来源选择、HDC 连续窗确认、映射目标、MPU 掌部目标及 LCD |

链路为：PL 特征 → 现有采集 DMA → PS 检查完整窗并提交描述符 → PL 经 HP1 读取 DDR → PL 运算及写回 → PS 展示和管理。
HDC 原型留在原有两块 32 MiB DDR 库内；PS 不搬运高维查询，也不计算 HDC 原型或相似度。
这是计算迁移，仍由 PS 调度逐窗任务及学习流程；不宣称完成了脱离 PS 调度的自主个体化控制状态机。
质心对照和 MLP 软件参考继续用于验证，它们不替代 PL HDC 的实际输出。

ARM 的 PL-control 构建通过 `pl_learning_api.h` 选择 PL 后端，软件 NMF/HDC 算术在预处理阶段排除；
PC/旧版构建保留 C 金模型用于回归。异常不会自动回退 ARM 运算。

## 接口与一致性

- 新模块 `emg_learning_accel` 使用 FCLK0 100 MHz，GPIO6 命令/状态地址为 `0x41260000/0x41260008`，ABI `0x12`。
- 新的 SmartConnect 将 32 位 AXI4 主机接入 PS7 HP1；采集与 LCD 继续走原有 HP0。
- 共享 scratch 为 `0x11100000..0x11100FFF`；HDC 库为 `0x12000000..0x15FFFFFF`。
  两者均为 normal noncacheable，每次交接使用 `DSB`；应用与帧缓存的缓存策略保持原设置。
- 地址必须 4 字节对齐并位于上述区间；每次 AXI 请求单独检查边界，错误响应使本次运算失败。
  超时后隔离运算核至复位，同时排空已经发出的 AXI 请求，禁止新任务覆盖未完成事务。
- 模型增长仍使用已有事务性 DDR 分配，无固定“3 个自定义”或“8 类”槽位。
  可用数量受实际 DDR、评分矩阵及运算时间约束。推理若超过 20 ms 不接入识别/机械手，避免拖累 25 ms 窗口节拍。
- 冻结验证期间 PL 只读原型；只有用户明确标注、完整提交的学习试次更新范围，建立模型阶段更新原型。
  更新或预测失败会取消候选和有效结果，机械手继续遵守现有来源/新鲜度保护。

## 资源调整

V11 实现基线：LUT 40,703、FF 36,220、Slice 13,117/13,300（98.62%）、BRAM 26.5、DSP 105。
因此把原有异步 FIFO 改为同步读 BRAM 预取，读指针仍只在下游接收时推进，保留每路 4096 字容量与双时钟 Gray 指针。
没有缩小采集缓存，新增读延迟由 ready/valid 协议吸收。

新运算核单模块综合：LUT 3,278，FF 2,943，BRAM 2，DSP 6；这些数字不含 GPIO 与 SmartConnect。
整机布局资源对比：

| 资源 | V11 | V12 | 变化 |
|---|---:|---:|---:|
| LUT | 40,703 | 36,417（68.45%） | −4,286 |
| FF | 36,220 | 40,463（38.03%） | +4,243 |
| Slice | 13,117 | 13,008（97.80%） | −109 |
| BRAM | 26.5 | 45.5（32.50%） | +19 |
| DSP | 105 | 111（50.45%） | +6 |

新增功能依靠 BRAM 替代 LUTRAM 才能容纳，Slice 余量仍小，不能把 LUT 余量视为可任意增加逻辑的保证。
整机布线后 WNS **+0.229 ns**、WHS **+0.036 ns**，全部用户时序约束满足；DRC 0 error。
`full_build.log` 中 G1 系数绑定、G2 网表系数解码、G3 常数 DSP 扫描、G4 时序全部通过，原验收规则没有放宽。

## 验证证据

- `learning_test.log`：64 组 NMF（零值、极小值、饱和及随机输入），六类各 120 次 PL 原型更新，26 组全类预测，逐位匹配独立 Python 整数参考。
  验证冻结原型、精确同分选择首类、零尺度、裁剪、饱和、AXI 各通道独立背压、错误响应、非法地址、超时和迟到响应。
- 同一测试中的 C 工作流覆盖正式 PL 分支：用户标签、完整试次范围提交、120 样本/类、冻结验证、追加类别、NMF/HDC 失败失效；计算桩不作为数值正确性证明。
- 仿真可变 AXI 延迟下，100 MHz 最大周期：NMF 3,958（39.58 µs），单次原型更新 23,863（238.63 µs），六类推理 77,188（771.88 µs）。
  这是所测 AXI 模型的核内时间，不包含真实 DDR 争用、PS 描述符和显示开销，也不是板上实测延迟。
- `fifo_test.log`：准确 4096 容量、满空切换、异步随机流、指针回绕、背压数据稳定和流中双端复位。
- `lcd_test.log`、`control_test.log`、`hand_test.log`、`sd_test.log`、`hdc_golden_test.log`：显示/导航、基础 PL 决策、机械手同帧复位保持、SD 和原软件金模型回归。
- `arm_build.log`：正式 ARM PL-control 应用编译。
- `learning_netlist_test.log`：综合后 DSP/BRAM 网表重放 64 组 NMF、六类各 4 次更新和 26 组 HDC 预测，检验综合后的数值与 ROM 内容。
  该测试等待 primitive 的 100 ns 全局复位后再发送命令；超时隔离由完整 RTL 测试覆盖。
- `add_pl_learning.log`、`ip_config.tcldict`：BD 验证与参数回读；本机没有 Vivado MCP，使用既有 Vivado 2025.2 批处理方式。

Vitis 已用当前 XSA 更新平台并重新构建 FSBL；`ps7_init.c` 与 XSA 内版本逐字匹配。
V12 打包脚本增加 RTL/工作流、综合后网表、FIFO、平台构建的 PASS 门禁；缺少任一证据则不打包。
