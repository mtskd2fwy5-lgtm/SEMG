Slice是放置LUT、FF等资源的物理单元。FF很空并不意味着这些FF能与任意LUT合放；存储用途、控制信号和连线需求都会限制打包。93.74%是已占用站点比例，并非所有这些Slice都已完全填满，也不能直接换算“只能再加833×4个LUT”。新增设计可能重新打包，是否可布线仍须完整实现。

既有整机布线时序通过：WNS +0.320ns、WHS +0.002ns、TNS/THS 0。来源为原 `design_1_timing_summary_routed.rpt`；全局最差建立路径位于显示时钟相关约束组，不能据此声称25MHz算法路径只剩0.320ns。PL算法时钟25MHz，不能用旧源文件注释里的100MHz估算当前吞吐。没有测得整机动态功耗、温升和所有PS任务CPU占用。

## 4. 个体化学习的存储规模

容量计算为净载荷，不是已映射的BRAM数。RAMB36物理容量36Kbit，但常用32bit/16bit数据映射不会自动充分利用校验位；端口、深宽、候选隔离和对齐还会影响Tile数。

| 项目 | 计算 | 净载荷 |
|---|---|---:|
| 一模型、每类1原型 | 8×2048×16bit | 32KiB |
| 当前+候选、每类1原型 | 2×8×2048×16bit | 64KiB |
| 一模型、每类3原型 | 8×3×2048×16bit | 96KiB |
| 当前+候选、每类3原型 | 2×8×3×2048×16bit | 192KiB |
| 训练特征保留 | 8类×120窗×8通道×uint32 | 30KiB |
| 通道/等级项存储 | (8+16)×2048bit | 6KiB |
| 单试次待提交特征 | 40×8×uint32 | 1.25KiB |
| 单查询编码 | 2048bit | 0.25KiB |

还需范围统计、分数/计数、模型版本和传输缓冲。候选模型可复用其存储做学习累加；取消试次可采用特征暂存或影子累加，不能无根据地为每个阶段都复制全模型。本预算没有多加第三个完整模型。

工程预留：完整单原型学习子系统约26–32个BRAM36 Tile；三原型约58–66个。包括训练特征和ROM，并为深宽组织留量，尚须RTL综合验证。若保留40维而非当前8路MAV，训练特征缓存从30KiB增为150KiB，额外120KiB不能忽略。

编码与匹配应按字/维度分时进行，不把2048维全部展开。仅匹配部分，8×2048个维度在25MHz、每维1–4周期时约0.66–2.62ms；三原型约1.97–7.86ms。此处未含编码、训练、总线和调度，不是端到端延迟承诺。40窗/秒、25ms调度间隔提供了复用空间；训练重放仍需分块仲裁，不能停住基础采集与判决。

## 6. 优化顺序及目标

本节在完整功能追加、基线测量之后执行。若直接追加实现失败，保留综合/布局布线报告和失败原因；可运行基线所需的最小调整另记，不把优化收益混算为追加成本。

### A. 深FIFO改BRAM：优先、保持缓冲能力

- 两条4096×64接口FIFO采用同步读BRAM，外部保持AXI握手；输出预取/保持寄存器处理读延迟，重新验证独立时钟、复位、满空和背压。
- 每路完整64bit映射约8 Tile，两路约16 Tile；常量位剪裁可能更少，本预算不先取该收益。
- 可争取净减少约7,000–8,200 LUT，BRAM增加约16 Tile。LUTRAM不会仅靠添加 `ram_style` 就正确迁入BRAM：当前异步读口必须调整时序组织。
- 不缩短FIFO，不降低raw/processed采样率。128ms缓冲来源于已有DMA停顿问题，不能为省资源恢复旧问题。

### B. 八路特征运算分时复用

- 当前八套窗口累加和事件运算约占10.2k LUT、12.6k FF。把通道状态/四段环形统计放入小BRAM，共享算术；保留相同400样点窗、100样点步长和五类特征的整数语义。
- 工程目标净减少约4,000–6,000 LUT、约6,000–9,000 FF、约12–14 DSP，增加约2–4 Tile。此为估算，未综合。
- 25MHz / 32k样点每秒平均约781周期/样点，平均吞吐充足；实际ADS输出突发、状态读改写和窗边界串行输出仍需按最坏时序验证，不能仅看平均值。

### C. 带通乘法跨通道共享

- 滤波55 DSP中，八路带通各6个DSP合计48。共享带通运算有明显余地；陷波/梳状现有设计已部分串行，不先假设还可同比缩减。
- 目标减少约30–40 DSP，LUT净减少暂按0–1,000计，通道状态存储额外约0–2 Tile。必须保持系数、乘加位宽、截断/饱和、输出顺序和延迟配对。
- FIFO与特征的收益更直接，先做前两项再决定滤波改动规模；不为DSP数字好看而降低信号质量。

### D. 原型精度与算法选择：验证后优化

- 每类累计120窗时，±1相加的原型范围为[-120,120]，在该严格上限下int8可精确表示；三原型若各40窗，范围更小。若今后持续追加学习，不能仍无条件假定int8足够。
- 受控计数+位精确验证后，三原型双模型净载荷可由192KiB减到96KiB，原型存储常见映射约少24 Tile，具体端口/组织决定最终值。初版预算仍保留int16，不靠未验证压缩宣称可容纳。
- 多质心备选的8类×3原型×8维×uint16×双模型仅768字节原型，另需训练统计/缓冲。其资源显著低于HDC，但当前HD001的质心97.5%和HDC95.16%只来自少量同次佩戴验证，不能作为跨天效果或最终选型结论。
- 不默认通过降2048维、删通道、删FFT或取消raw存档来达成资源目标；这些会改变行为或准确率，需要单独证据。

因此最终功能更多，但LUT/FF/DSP可以比现在更少，代价是更多BRAM和更多运算周期。若做三原型且坚持int16双模型，BRAM成为下一个主要约束；不应再同时无预算扩类、扩维、扩训练缓冲。int8条件化压缩或经验证的多质心可以进一步释放BRAM，不纳入上表保守承诺。

## 8. PS/DDR与带宽补充

本轮读取实际ELF节表，避免把 `size` 的汇总bss（包含独立DMA保留段）误判为应用区占用：

- APP区静态代码/常量/变量合计2,320,300字节，约2.21MiB，占4MiB APP预算55.32%；剩余1,874,004字节约1.79MiB尚需容纳栈与后续增长。链接器至少保留64KiB栈；APP余量不是整块DDR余量。
- HDC当前对象66,880字节，约65.31KiB，位于PS DDR，不消耗上述PL BRAM；最终迁入PL后仍需PS模型文件/传输管理缓冲，不能把它全部算成可释放内存。
- DMA区独立保留1MiB；800×480三帧RGB888为3,456,000字节约3.30MiB，1024×600为5,529,600字节约5.27MiB，均不在4MiB APP区内。
- raw+processed导出64bit打包流约512,000字节/秒，再加特征/结果。若另记40维、40窗/秒的uint32特征，净载荷增加6,400字节/秒，另有标签/序号/分数。UART、SD、PS绘图调度是独立约束，不能因PL算力足够便声称不会丢包。
- HD001单窗学习页对照峰值3.398ms，相当于25ms调度间隔的13.6%，只是这段处理的时间比例，不是整个PS CPU占用率；没有把空闲时长或其他UI/存储耗时测入。
