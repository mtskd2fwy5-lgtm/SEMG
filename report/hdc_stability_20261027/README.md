# V16 HDC 稳定判决修复

本版针对已通过学习验证的 HDC 在保持动作时瞬时类别抖动、主页频繁回到等待的问题。修改 PS 的识别后处理和显示，复用 V15 的 PL 位流、XSA、FSBL、HDC/NMF 运算及模型接口；不重新综合硬件。

## 判决规则

- 普通动作：最近 5 窗至少 3 个合格票；相对其他类别至少领先 2 票，或当前为连续 3 个合格同类窗口。干净的动作切换仍需 3 窗（更新周期 25 ms）。
- 放松：最近 8 窗至少 6 个合格票。确认结果必须得到当前窗口支持。
- 分数间隔小于 2% 的窗口弃权，不再立即清空全部历史；原有分数和量化门槛不降低。
- 已确认类别只允许短暂保持；没有新的确认支持满 8 窗或 200 ms 时失效。类别持续交替不会维持旧动作。
- 模型验证不通过、量化超范围多于 1 路、序号断裂、数据超过 250 ms 未更新仍立即失效；机械手的 MPU、标定、映射、主动启用和链路保护保留。
- 学习页在完成验证后的自由识别使用与主页相同的稳定类别。学习、独立验证、CSV 评分及原始分数间隔仍使用单窗口预测，不用平滑结果提高验证正确率。

## 验证

`lcd_test.log`：真实特征包解析、实际 HDC 预测、单窗错类、精确同分弃权、持续交替失效、量化与模型门禁、虚拟映射、144 条页面路由、两种 LCD 分辨率及帧像素一致性。

`hand_test.log`：单窗错类/低分容忍、真实换类、持续不确定 STOP、放松确认、完整动态类别编号、序号与时间回绕、数据断裂、PWM 队列/ACK/复位和映射保护。

`learning_workflow_test.log`：生产 PL 后端失败时模型与 NMF 结果失效，不回退到软件算法。

`regression_sources.json` 将回归结果绑定到本次测试的固件与测试源码。`artifacts.json` 记录 V15 硬件继承核对、未修改固件的逐项继承核对、BOOT 位流分区、应用及 FSBL 加载段检查。

回归入口：`powershell -ExecutionPolicy Bypass -File build/scripts/run_hdc_stability_test.ps1`。

## 使用与边界

更新 BOOT 后需重新完成静息校准与 HDC 学习、独立验证，再比较学习页和主页的同一保持动作。模型保存在 RAM，重新上电不会继承上次学习结果。

疲劳参考为前 8 个有效 FFT 窗（4.096 s），固定预热为 16 窗（8.192 s）；期间动作切换或无效窗会重新建立参考，实测等待可能达到 10–15 s。本版不修改此时长或疲劳阈值。保持动作一分钟仍显示正常/未疲劳是可能的：现有等级依据相对参考的 MDF 下降（10/20/30%）和连续确认，不按保持时间自动升级，也不能据此排除主观疲劳。

自动测试覆盖软件行为，不代表用户手势的实板识别率已经验证。镜像未自动写入 SD 卡，未下载或驱动机械手。
