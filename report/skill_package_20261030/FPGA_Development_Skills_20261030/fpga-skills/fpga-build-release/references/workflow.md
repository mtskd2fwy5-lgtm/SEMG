# 构建、优化比较与交付

## 输入模板

填写工程根目录、目标器件、工具版本、顶层/源清单、IP/参数/初始化文件、时钟和 I/O 约束、构建入口、基线、修改范围、交付格式。缺项先查工程设置；只确认阻碍当前步骤的信息。无处理器就不要求固件、FSBL 或 XSA。

## 执行与输出

1. 保存源码/约束/IP 配置/初始化文件的版本与哈希，记录工具命令。查看实际 compile order 与 run 输入，不仅看编辑器里打开的文件。
2. 验证实际参数及类型。IP 包装、module reference、OOC run 可能另有参数和缓存；源声明正确不代表实际实例正确。更改后检查生成包装及日志，避免无证据地重建所有 IP。
3. 依据改动运行参考与 RTL；影响综合语义或初始化时检查实际网表/存储内容。集成测试验证实例连接和时钟/复位，不只测独立模块。
4. 从实际实现报告读取资源、时序、未约束路径与检查项。WNS 为正不代表所有 CDC、I/O 或方法学问题消失；按原检查含义审查。不能以删除约束、滥设 false path 换取“通过”。
5. 对照基线记录 LUT/寄存器、BRAM、DSP、Slice/ALM、控制集、WNS/WHS、吞吐与延迟。功能、精度或接口改变时单独列出，不冒充等价优化。
6. 交付匹配的生成物及 manifest：输入标识、工具、约束、产物哈希、测试与范围。核对打包实际内容，不仅验证同名文件存在。下载/写卡后再确认运行版本及板端行为。

AMD Zynq 适配时核对 XSA、位流、FSBL 初始化、应用所有有效加载段和 BOOT 分区；其他平台按自己的配置/固件格式检查，不照抄字序、地址或头长度。

## 独立资源比较脚本

`python scripts/compare_resources.py baseline.json candidate.json`。只需 Python 标准库，输出 JSON 到 stdout。两份文件结构相同，例如：

```json
{
  "metadata": {
    "target": "your_part",
    "tool_version": "your_version",
    "stage": "routed",
    "constraints": "actual_constraint_bundle_hash",
    "workload": "algorithm_io_clock_test_contract_v1"
  },
  "metrics": {"lut": 100, "ff": 200, "dsp": 8, "wns_ns": 0.1, "latency_cycles": 400}
}
```

候选填实际指标；元数据必须相同且非空，指标键一致且为有限数值。constraints 使用实际约束集合哈希；workload 包括时钟、通道/数据宽度、算法/模型与测试负载等。工具不能判断填写的元数据是否真实，需人工对照原报告。

基线非正时相对百分比为 null；时序余量改善不自动推出 Fmax。吞吐/延迟写明单位和起止点，测试条件不同则另表解释，不硬拼百分比。

## 失效与验收

日志未绑定当前输入、比较阶段不一致、初始化或 ABI 不匹配、只测了替代软件分支时，不能认定发布通过。输出已验证范围和阻塞点，可继续诊断而不强行交付错误版本。
