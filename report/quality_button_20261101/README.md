# V24 一键全通道质量检查说明

V21 引入的评分限流解决了界面卡顿，但通道检查页暴露出两个剩余问题：八格分数逐个冒出而非同时显示，且一轮维持八通道实时评分所需的计算量超出普通页面额度，先出分的通道会因 1.5 秒"无新数据"判定而闪烁。V24 将该页从连续后台评分改为按键触发的一次性全通道检查。

## 交互语义

| 项目 | V23 | V24 |
|---|---|---|
| 触发方式 | 后台持续评分 | 质量页底栏"全通道检查"按钮，按下一次执行一轮 |
| 采样窗口 | 各通道独立滚动窗口 | 按下后八路丢弃旧窗口，从同一起点各采 4000 样本（1 秒 @4 kSPS） |
| 结果提交 | 每通道算完即更新一格 | 八路全部完成后一次性提交，八格同时刷新 |
| 后台计算 | 一直运行（受 0.5/1.5 ms 额度限制） | 仅检查激活期间运行，额度固定 2.5 ms / 5 ms；平时完全停止 |
| 无数据通道 | 按各通道过期判定 | 既无实时流又无冻结检查窗口则立即判"无数据"；活流但分析慢由 8 秒兜底超时收尾 |
| 结果保持 | 随新评分刷新 | 检查完成后持久显示，调整电极后再次按下复查 |

按下瞬间丢弃已有的冻结窗口与半满窗口并中止在飞 worker 任务，保证八路窗口起点一致。检查进行中重复按下被忽略，不排队。数据断流仍按 1.5 秒判定；8 秒超时（`CQ_CHECK_TIMEOUT_TICKS`）仅在个别通道分析远慢于预期时兜底，正常一轮远早于该时限完成。评分公式、FFT 数据、滤波与其余页面行为均未改变。

检查期间按钮显示"正在检查 N / 8 路"进度，完成后状态栏提示调整电极后可复查。页面渲染与时间无关（不显示"X 秒前"类文本），保证增量帧与全量帧逐字节一致。

## 验证

- `quality_test.log`：AC RMS、偏置、四次工频谐波、满量程、静默、序号回绕/断流/重复、无基线评分、漂移工频、冻结窗口取消/背压、来源/包头拒绝，以及新的按键全通道检查——同窗采集、单点提交、重复按拒绝、断流判无数据、无流立即提交。
- `budget_test.log`：检查间空闲（有 pending 数据也不消耗预算）、检查激活时 2.5 ms/5ms 额度边界、单机会单块、单次提交；扫描内容更新率与静态零位回归。
- `numeric_validation.log`：独立 NumPy/SciPy 数值对照，评分公式未变。
- `lcd_test.log`、`imu_test.log`：800×480、1024×600 双面板完整界面回归——未按下不评分、按下后八路同窗齐评、残余工频/尖峰检出、无基线、结果持久、触摸下钻（磁贴聚焦/通道波形/通道频谱/返回），以及 144 路导航生命周期、HDC 各页、康复训练等既有回归。
- `hand_test.log`、`learning_workflow_test.log`：机械手与 PL 学习后端回归。
- `baseline/manifest.json`、`regression_sources.json`：V23 基线哈希绑定与本轮全部验证输入；发布验证逐项确认继承 V23 位流、XSA、FSBL 与控制实现，BOOT 再核对加载段。

尚未上板：实际触摸体验、一轮检查的端到端耗时与检查期间 FPS 需在板上观察。串口开启诊断 `d` 后，`[STAT]` 中 `quota_us` 在检查激活时为 2500、平时为 0；`lcd content_fps10` 为画面内容更新率的十倍。

## 使用

启动镜像：`build/boot/BOOT_20261101_HAND_CONTROL_HDC_DYNAMIC_QUALITY_BUTTON_V24.BIN`。

进入"通道质量"页后点击底部"全通道检查"按钮即可获得八路同一窗口的评分结果；其余操作流程与 V23 一致。
