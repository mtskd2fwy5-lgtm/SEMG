# HDC 在线学习可行性复验（2026-10-24）

结论：可以在现有八通道 MAV 后增加 HDC，作为**有标签、可撤销的校准候选**。当前证据不足以宣布“自愈验证通过”、优于 MLP，或直接将 HDC 接入机械手控制。建议先与更简单的通道缩放 MAV 质心一起做旁路验证，取得新佩戴数据上的收益后再决定迁入 PL。

本轮只新增离线审计脚本、测试及报告，没有修改生产模型、PS/PL 固件或 BOOT。

## 原截图的结论为什么需要收窄

已读取 `tools/hdc_validate.py`、`tools/nmf_validate.py`、`data/metrics/hdc_validate.json`、原 MLP 验证报告、现有自校准实现及已布线资源报告。

1. `proto[true] += query; proto[pred] -= query` 确实能低成本逐样本更新，但 `true` 来自每一个测试窗口的真实标签。代码先预测后更新，是合法的**有监督流式预测后学习**；它不是无需标签的自主适配。普通监测和机械手运行时，系统不知道哪个预测错了，也不知道应改成哪类。康复训练的“目标动作”也不自动等于用户实际完成的动作。
2. 八份记录中，七份的前 30% 训练窗口缺少至少一种后续测试动作，只有 EMG009 五类齐全。冻结模型甚至没有学过部分动作；后续有标签更新同时完成了“补学新类别”和局部追踪。不能把全部涨幅都解释为电极漂移适应。
3. 100 ms 窗口、25 ms 步长，相邻窗口重叠 75%，动作标签连续保持多秒。作为诊断，直接输出“上一窗口真实标签”也能达到平均 **99.70%**。这个不可部署的参照说明：持续提供真实标签会让连续动作段预测容易很多；原实验仍有价值，但评价目标与无反馈识别不同。
4. 图中 HDC 对 EMG013 约 79% 与旧 MLP 65.1% 采用了不同训练/测试协议、不同窗口集合和不同标签可用性，不能作为 HDC 战胜 MLP 的同条件证据。也没有直接证据证明 MLP 的权重确实学到了 CH6 伪迹。
5. 原 VIM 的各量化等级独立随机，相邻幅值等级也会对应明显不同的向量；它没有保留标量幅值的邻近关系。本轮额外测试了逐级翻转部分位的有序 VIM，作为新候选单独报告。
6. 96 条历史结果是 **12 个 D/Q 配置 × 8 份记录**，不是 96 个配置各跑八份。原型可以增量更新并非 HDC 独有；MLP 也能逐批 SGD 更新，代价、遗忘风险及验证方式不同。

原 D/Q 扫描每个配置只有一个随机初始化，且各配置使用不同种子；平均分接近只支持“可先选择较小维度做候选”，不证明维度完全不敏感或 Q=16 已最优。本轮固定 D/Q 后增加了三个种子，仍需新数据验证选择结果。

## 复现原实验

固定 D=2048、Q=16、原随机种子规则，八份记录的冻结及在线准确率均复现到历史 JSON 的四位小数精度。

| 原协议，八份记录等权平均 | 准确率 |
|---|---:|
| HDC 冻结 | 41.03% |
| HDC 每窗获得真值、错误后更新 | 73.56% |
| MAV 质心冻结 | 57.97% |
| 上一窗口真值诊断参照，不可部署 | 99.70% |

这些数字只描述原协议，不是新固件准确率，也不是无标签适配效果。截图约 41.7%/73.9% 涉及其他 D/Q 汇总，不能与本轮固定配置逐项混用。

## 更接近板端的校准验证

复用现有 `train_board_model.feature_windows`：4 kSPS、400 样本窗口、100 样本步长，每个标注动作段首尾各去除 1 秒。仅用最终 processed 波形，不重复施加 PC 滤波。检查实际时间戳连续性、信号来源、类别和采样率。

- 对每类，取第一个足够长动作段的前 40 个稳定窗口校准；每类相同数量，避免原型强度因类数量不同而失衡。
- 所有校准动作段结束后，才开始测试；测试用后续完整动作段。校准与测试不共享动作段或原始采样点。
- 量化满量程仅由校准窗口计算；测试不参与阈值/原型拟合，不清理测试尖峰，参数全程冻结。
- D=2048、Q=16；随机种子 7、17、27。累加原型与五轮错误纠正两种训练方式分别测试；每次加减都模拟有符号饱和。
- 五类动作必须在后续测试中齐全。EMG014、017、018 在完成五类校准之后，没有再完整重复五类，故不参与该协议的平均分；其原实验复现仍保留。

| 方法 | 五份记录等权平均准确率 | 平均宏 F1 |
|---|---:|---:|
| MAV 质心 | 69.48% | 68.14% |
| 按校准满量程缩放通道的 MAV 质心 | **74.54%** | **71.24%** |
| 原随机 VIM，16 bit 原型，直接累加 | 67.92% | 64.69% |
| 原随机 VIM，16 bit 原型，五轮纠错 | 69.50% | 66.11% |
| 有序 VIM，16 bit 原型，直接累加 | 73.42% | 70.28% |
| 有序 VIM，16 bit 原型，五轮纠错 | 73.21% | 68.17% |

| EMG008 | 2436 | 85.6% | 85.0% | 70.0% | 81.2% |

## PL 的资源与接口可行性

截图将可加减的整数原型按 1 bit 计算，混淆了“二值查询向量”和“整数原型”。现有 Python 原型实际为 int32，每维有权重；其相似度需要带权加减累积，不能完整等价为一次 XOR/POPCNT。

D=2048、Q=16、八通道：CIM/VIM 编码表合计 **6 KiB**。

| 五类原型格式 | 单份原型 | 编码＋单份原型的理想 BRAM36 下限 | 再留一份原型备份的下限 |
|---|---:|---:|---:|
| 1 bit 多数符号，改变算法 | 1.25 KiB | 2 | 2 |
| 8 bit 饱和整数 | 10 KiB | 4 | 6 |
| 16 bit 饱和整数 | 20 KiB | 6 | 11 |
| 原 Python int32 | 40 KiB | 11 | 20 |

下限按每 BRAM36=36,864 bit、理想容量装填计算，不含端口/宽深映射、缓存、计数器、置信度计算及存储碎片。16 bit 分开存编码表与原型时容量取整已约需 7 个 BRAM36，尚未综合。备份表中只额外计算原型，未额外计算量化阈值/元数据。

若未来扩至 14 类，16 bit 单份原型 56 KiB，加编码表的理想下限为 **14 BRAM36**；保留一份原型备份时为 27。当前五类流程、协议和校准界面不会自动因此支持 14 类。

采用串行/分时加减与比较，**可以设计为不使用 DSP**，但没有本轮综合证据。每秒 40 窗、五类相似度约需 409,600 次维度累加/减法，另有编码和学习开销，25 MHz 下有实现空间。全并行展开会增加 LUT、扇出与布线，不应因维数可位运算就视为零成本。

已布线系统实际占用：Slice 93.74%、LUT 72.12%、BRAM 29.5/140、DSP **整机合计 95/220**；WNS +0.320 ns、WHS +0.002 ns。容量上 BRAM 有余量，布局布线余量需要重查。不能只按 BRAM 或 DSP 容量宣布可直接插入。

## 建议接入方式

1. **先旁路**：复用现有稳定八通道 MAV，保留 MLP 为生产决策源；HDC 和缩放 MAV 质心只记录候选结果。现有 NMF/协同已有 PS 计算与 LCD 展示，不必为了 HDC 先重建整个协同模块。
2. **明确标签**：复用自校准界面的五类引导，稳定后经用户确认采样；覆盖轻力度与舒适力度。不能仅因训练页面要求握拳，就把整段输入都当作真实握拳；不能用 MLP 的预测宣称 HDC 获得了独立真值。
3. **保留独立动作段**：第一轮拟合，第二轮验证；同一批验证数据若用于选 HDC/质心/编码参数，还需第三轮或新佩戴数据作最终测试。先固定准入规则，再看测试结果。
4. **仅在校准/确认纠正期间更新**：普通训练与机械手工作阶段冻结。缺帧、接触异常、动作过渡、校准取消时暂停学习。检测质量不能保证手势标签正确，也不能修复断路电极。
5. **候选、验证、应用、撤销**：失败保留原 MLP；存量化阈值、通道顺序、环移配置、编码种子、模型版本及校验信息。改变环移/通道布局后应重新验证 HDC，避免坐标不一致。HDC 相似度差不是校准后的概率，不能与 MLP softmax 百分比直接平均。
6. **确认收益后再做 PL**：先实现定点参考与跨实现逐位测试，再独立 RTL 仿真、综合和整机布局布线，最后生成匹配 BOOT。HDC 的原始 argmax 不直接连接 PWM，继续通过最终决策、过渡确认和失效处理。

建议进入下一阶段的依据应是：在相同校准时长、相同保留测试段、相同标签可用性下，相比原 MLP 与缩放质心有稳定收益，同时不增加静息误触发和动作跳变。现有结果支持继续研究，**尚未满足默认启用在线自学习的条件**。

## 复现与产物

```powershell
D:/PYTHON/python.exe -m unittest sim.test_hdc_audit -v
D:/PYTHON/python.exe tools/audit_hdc.py
```

- `tools/audit_hdc.py`：审计与受控校准验证，不导出或覆盖生产模型。
- `sim/test_hdc_audit.py`：六项测试覆盖动作段隔离、缺类拒绝、逐次饱和、冻结预测不变性、编码可重复性、资源位宽计算。
- `audit.json`：逐记录原协议复现、训练缺类、独立验证混淆矩阵、随机种子、饱和计数、资源下限、输入/代码 SHA256。
- `verification.json`：六项单元测试通过、16 个历史准确率复现检查通过，以及代码和输入摘要一致性记录。

没有本轮 HDC 上板验证、综合报告或新 BOOT。原生产实现仍保持不变。
