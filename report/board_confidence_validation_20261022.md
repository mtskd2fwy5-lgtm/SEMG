# 板端置信度与姿态门控复核

日期：2026-10-22。评估模型为已导出的 `nn_int8_board_multiwear`，数据为未参与模型拟合的 EMG017。仅增加验证脚本和报告，未改变权重、固件或 BOOT。

## 主要发现

1. 原先报告的 INT8 87.84% 可复现，但它只衡量 argmax，未计入 PS 门控与姿态确认。
2. 当前百分比为 `max(logits)*100/(sum(abs(logits))+1)` 的整数分数，不是概率。原始稳定窗口中，平均分数为 29.70；9.48% 原本正确的非静息预测低于当前 30 分阈值。
3. `pose_observe` 对低分窗口立即输出静息；重新进入动作需要连续两窗确认，因此短暂低分会造成动作与静息之间的跳动。此前“保持原姿态”的描述不准确。
4. `pose_observe` 在类别、MAV 门控标记均不改变时，不刷新 `pose_active_conf`；LCD 数值可能停留在上次接受姿态时的分数，并非当前窗口分数。
5. 当前 30 分阈值能有效减少静息误触发，也会损失张手、屈腕，尤其伸腕的召回率。直接换 Softmax 并不能自动解决概率校准问题。

## 可复现方法及边界

命令：`python tools/verify_board_confidence.py --c-check`。

首先沿用训练工具每段前后各去除 1 秒的窗口提取，得到原报告的 8649 窗口，复现 INT8 87.8367%。

随后从 CSV 开头按 400 点窗口、100 点步长建立连续网格，状态机跨越全部动作转换持续运行，不在标签边界重置。仅评分标签内部前后各避开 1 秒、并已结束模拟校准的 8579 个稳定窗口；边界、校准期仍参与回放，但不计入此准确率。网格对齐不同，因此连续网格 argmax 为 88.16%，不可将其与 87.84% 的差异归因于门控。

固件静息基线未写入此 CSV，无法恢复实际板端 MAV 门控。MAV-on 场景假设在 CSV 开头启动校准，丢弃 80 窗后收集 16 窗；这些窗口实际均标为静息。得到基线 `[4489,3404,4444,4695,4251,8175,4143,5540]`，门限按固件取 `max(3*baseline,1000)`。该场景不能称为实际硬件识别准确率。

从现有 `main.c` 原样抽取 `logit_conf` 与 `pose_observe`，编译为宿主 C 程序；无 MAV 与模拟 MAV 两个场景共 **21774 条置信度/姿态输出全部逐条一致**。保留了 C 的 uint32 运算规则；LCD 几何插值、渲染刷新调度及硬件包时序未重现。

## Softmax 与后续验证

Softmax 对照先将 INT32 logits 乘导出的 `logits_scale=0.0010796425800253476`，再作稳定 Softmax。缩放对 argmax 无影响，但对 Softmax 有影响，不能把未缩放的整数 logits 直接当作浮点 logits。无 MAV 场景下，Softmax 阈值 80% 和 90% 的稳定段准确率分别为 93.33% 和 94.65%，静息误触发率仍为 17.02% 和 12.69%。这些输出尚未校准，不能将其解释为真实正确概率。

本次所有阈值扫描均为 EMG017 上的探索，97.04% 与 95.65% 不能作为新选定参数的独立测试成绩。建议将 20–25 分作为下一轮候选，在独立校准批次选择策略，再用新佩戴记录评估最终准确率、静息误触发和动作响应。需要记录真实 `[CAL] baseline/threshold` 及逐窗 R 行才能验证实际板端 MAV 门控；采集训练不应据动作标签给线上门控提供信息。
