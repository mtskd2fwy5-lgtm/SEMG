# 协同平滑显示与握拳相对强度训练

日期：2026-10-23。基于当前 PL 独立决策固件，PS 增加反馈与训练条件；本轮不修改 RTL、模型或原始/最终滤波波形。尚未在实物验证本轮新增功能。

## 使用

候选镜像：`build/boot/BOOT_20261023_GRIP_FEEDBACK_V1.BIN`，构建标识 `20261023_GRIP_FEEDBACK_V1`。备份启动卡原文件，将候选复制为 `BOOT.BIN` 后断电重启；本次没有自动写 SD 卡，没有覆盖工程默认 BOOT 或先前 PL-control 候选。

1. 协同页中，`C=` 仍为每窗原始系数；下面的“平滑”、活动条和最近 10 秒趋势使用平滑值。三个协同分量均处理，参考刻度仍为 EMG008/009 固定参考，不是力量百分比。
2. 进入“康复训练”，选择握拳，保持舒适、可重复的抓握，点击“采舒适参考”。保持约 3.5 秒：前 0.5 秒用于稳定，后 3 秒计算原始 C2 均值。可以用电子秤帮助保持一致，但本固件不接收秤数据，也不换算实际力。
3. 开启“握拳强度”，点击开始训练，然后按提示放松，完成原静息校准。握拳阶段要求正确动作和新鲜的同窗协同数据，并使平滑 C2 在个人参考的 80%–120% 范围内，才能累计连续保持时间；越界或动作不符重新计时。
4. 提示分别为“活动不足”“目标范围内”“活动偏高”；没有对应窗口则显示“等待同窗数据”。其他动作继续按原动作与保持规则评估；四动作组合中仅握拳增加强度条件。强度开关默认关闭，未采有效参考时不能启动包含握拳的强度训练。
5. 本次参考仅在 RAM 中，重启或切换监测/串口采集模式后清除。重新佩戴、接触调整或改变抓握方式后，应重新采参考；系统无法自动发现重新佩戴。仅重做静息校准不会重采抓握参考。

采参考时离开训练页、打开菜单、停流、窗口缺失或采样超时会提示失败，不使用部分样本。此参考依赖用户实际执行舒适抓握，不是由分类器或测力传感器自动确认的 MVC 标定。近零 C2 不能形成参考；尚未设置“参考波动过大”自动验收指标。

## 实现及边界

- `synergy_feedback.h` 旁路接收固定 W 求解后的原始 C，指数平滑系数 1/8，25 ms 步进。时间常数约 187 ms，阶跃到 90% 约需 450 ms，此外原 MAV 还有 100 ms 窗口；不能把它称为无延迟滤波，也不能用平滑后的稳定性替代原始测量稳定性。
- 原始 C、NMF 基底、残差、MLP 和 PL 门控/稳定决策未改变。平滑不限制 C 数值上限，仅活动条/趋势按原参考显示范围截到 100%。波形 raw/processed 及其 UART/SD 记录保持原格式，可以用于离线重新计算原始 C。
- 保存最近 8 个特征窗口的序号和 C2，决策必须找到同序号、75 ms 内的数据才能用于强度判定，不能重复使用上个窗口的显示值。特征在决策之后到达或遥测丢失时，该决策不获得保持时间；没有重排补算。如果实物长期显示等待同窗数据，应采集包顺序检查，不能解除同窗限制掩盖问题。
- 只有相邻的新决策能累计时间，重复序号、丢窗、数据中断、低支持度或 PL 未就绪不能得分。强度条件在 PS 康复任务引擎执行，PL 识别决策仍独立运行。
- RHnnn.CSV 增加开关、Q8 C2 参考、80/120% 边界、被评估握拳窗口数及动作正确且在范围内的窗口数。开启强度时响应定义改为提示到动作及强度均满足。窗口数按 25 ms 重叠特征窗统计，不是独立试验样本，也不是力值精度。
- C2 抓握相关性来自当前用户定性观察与电子秤对照，没有本次测力同步原始数据。不同动作、手腕姿势、疲劳和接触变化均可能改变 C2；不能用于宣称测力准确率，也没有驱动机械手。

## 验证与构建

- `run_grip_feedback_test.ps1`：快速交替噪声衰减、原始输入保留、序号/时钟回绕、缺窗重置、参考完整性、零值/满量程、采样超时、80/120% 精确边界、动作与新鲜数据约束，以及其他动作不受强度条件影响。
- `run_rehab_test.ps1`：原单动作/组合、保持/休息、支持度、超时、暂停、序号和时间边界回归。
- `run_synergy_test.ps1`：真实 NMF C 实现与独立浮点参考的 EMG008/009/018 回放；原始 C 数值验证仍通过。
- `run_lcd_firmware_test.ps1`：真实固件在 800×480、1024×600 的参考采样、按钮、启动保护、同窗保持、数据缺失与 CSV 内容，兼有原显示/字体/触摸/波形/频谱/康复回归。PNG 为真实 host 渲染，并非实机截图。
- `pl_control_firmware_test.c`：PL authoritative word 与同窗 C2 配对，缺失特征不累计；原 PL 权限、epoch、失效状态和二进制输出回归。`run_uart_record_test.ps1` 验证两种串口采集来源的二进制帧不受影响。
- ARM 编译检查修正了本次发现的 ARM `uint32_t` 与现有 `u32` 底层类型不同造成的指针类型告警，未使用强制转换掩盖。最终日志仅允许原供应商 FatFs 未使用变量告警。

候选打包复用 `build/boot/build_pl_control_boot.ps1`；现默认生成本轮独立镜像。先验收现有 PL G1–G4，再编译 PS，打包前检查 ELF 的构建标识，打包后检查 XSA/bit 一致、BOOT 完整 PL 分区和 PS 所有非空 PT_LOAD 字节。最终结果和 SHA256 见 `boot_build.log`、`artifacts.json`。本轮复用已布线硬件，不能把 PS 软件测试描述为新一轮 PL 综合或新的全系统 CDC 签核；原告警及硬件余量见 `../pl_control_20261023/README.md`。
