# 手掌默认姿势、抬臂方向与动作后漂移优化

日期：2026-10-14。固件标识：`20261014_LCD_TRACK_V4`。

依据用户确认：ATK-4384（800×480），左手，MPU6050 固定前臂，X 朝小指侧、Y 朝手肘。用户补充：翻不翻掌，抬臂方向都相反；漂移主要在翻掌、抬臂后偏离。本次针对这个全局方向错误与动作后误差修改，不把问题归因于仅翻掌后的显示反转。

本报告取代 [上一版报告](lcd_3d_touch_20261014.md) 中的默认手背、姿态映射、零偏采集、量程及当前镜像信息。三维模型、GT911 触点地址修复、三帧缓冲与菜单继续使用已有实现。

用户随后补充手腕伸屈也反了，最终版本一并修正。姿态合同中类别 3 的 `wf=+34°` 表示腕屈，类别 4 的 `wf=-34°` 表示腕伸。LCD 旧局部变换对 `wf` 额外取负，造成弯向手背与弯向掌心互换；改为正 `wf` 绕模型 X 轴，先朝掌心 +Z 弯曲，再施加前臂整体姿态。腕关节支点与前臂保持原位置，翻掌不会改变关节角的解剖意义。同时修正负 Q8 角度的舍入，避免 −34° 被截断成 −33°；肌电类别与共享模板值沿用原合同。

随后实机现象显示上电静止约 5 秒才开始跟随。根因是旧流程把三维矩阵更新放在 `mpu_zero_valid` 之后，静止零偏窗口一旦被抖动重启，整只手就像卡住。V4 将“实时姿态跟随”和“零偏完成”分开：收到首个有效六轴样本即建立临时姿态并更新矩阵；零偏仍在后台连续稳定采集，运动时重启窗口。状态文字改为 `MPU WAIT`（尚无有效数据）、`MPU TRACK`（正在跟随并采集零偏）、`MPU READY`（零偏完成）。带少量加速度与陀螺噪声时，主机回归要求两秒内完成稳定窗口。

校准姿态的含义需要区分“默认姿态”和“实际姿态”：未收到有效数据前的备用画面默认掌心朝上；有效数据到达后，零位画面反映传感器当时真实朝向。若校准期间实际手掌朝下，校准后显示掌心朝下是预期结果，并非再次把画面翻反。若希望校准后初始画面为掌心朝上，应在掌心朝上、前臂朝前且静止时发送 `z` 或点击“MPU校准”。

## 修改

默认未校准姿势为掌心朝上，矩阵为 `diag(-1,+1,-1)`。有效校准后，根据实测重力显示实际的掌心、手背与侧面，不强制遮蔽另一面。上电或重新校准时清除旧姿态显示键，避免旧的倾斜残留在等待校准画面中。

模型采用 x 横跨手掌、y 从腕向指尖、z 朝掌心；相机世界坐标为右、前、下。按已确认安装方向，传感器 Z 朝手背，与模型掌心方向相反。旧实现将传感器旋转用 `B=diag(-1,-1,+1)` 两侧转换，没有正确表达这套坐标。现在先旋转传感器中的模型基向量，再投影到校准时建立的固定右、前、下基底。向上由平均重力确定，向前由传感器 -Y 的水平投影确定；翻掌不再重定义抬臂方向。四元数积分和重力校正仍在一致的右手传感器坐标中进行。

默认相机距离从 660 改为 800，垂直偏移从 -200 改为 -260，保留固定眼位、透视与肘锚点。这样抬臂时手指不会像旧预览那样在约 30° 就被顶部裁去。透视投影的屏幕位移随视角改变；三维升降方向由世界坐标确定，屏幕像素位移并非与抬臂角度线性对应。

动作后误差的处理包括：

- PL 的 `GYRO_CONFIG(0x1B)` 从 `0x00` 改为 `0x10`，量程由 ±250 改为 ±1000°/秒，PS 换算同步为 32.8 LSB/(°/秒)。旧量程有快速翻掌截断角速度的可能；没有实机原始数据，未认定这是本次所有漂移的唯一原因。
- 校准窗口要求 100 个不同且连续稳定的采样。角速度突变、明显运动、加速度变化或窗口内重力方向移动会重启窗口；拒绝近竖直前臂零偏采集，以避免水平方向退化，但不会阻塞临时姿态跟随。V4 仅对稳定性判断加入约 50 ms 低通，实时姿态仍使用原始运动输入，避免相邻原始样本抖动反复清空窗口。稳定的启动零偏可直接采集，不依赖旧滤波姿态归零。
- 校准结束时用平均重力重新初始化姿态，避免校准之前的运动积分残留。掌心接近水平朝上时采用数值稳定的重力初始化分支，保留小倾角。
- 运行时，在持续静止后缓慢更新温漂零偏，抑制残余偏置继续制造旋转。静止阈值为各轴残余角速度低于 0.8°/秒且重力稳定，持续约 0.5 秒。非常缓慢的绕重力轴转动可能被视为静止；2°/秒的有意转动已纳入回归并能跟随。
- 运动中降低重力校正增益，校正角速度上限为 0.25 rad/s；明显偏离 1g 时不作重力校正。即使模长接近 1g，线加速度也可能污染方向，因此测试同时包含模长改变与模长保持的干扰。
- 四元数积分分成不超过约 5 ms 的子步；跨过 80 ms 的服务缺口或超过八个采样的序号跳变时跳过积分，并计数。缺口内没有采集到的转动无法可靠补回，尤其是航向。

LCD 状态文字改为两倍字号的 `MPU WAIT` / `MPU TRACK` / `MPU READY`。监测模式发送小写 `i` 可输出：

```text
[IMU] fw=20261014_LCD_TRACK_V4
[IMU] zero=... samples=... still=... gaps=...
[IMU] bias_mdps x=... y=... z=... clip=...
[IMU] track=... seq=... accepted=... generation=...
[IMU] zero_restart=... reason=0x... dt_ms=... age_ms=...
[IMU] acc_lsb x=... y=... z=...
[IMU] gyro_lsb x=... y=... z=...
```

`bias_mdps` 单位为千分之一度/秒；`clip` 为各轴接近 ADC 满量程的累计次数，`gaps` 为跳过积分的缺口次数。诊断绕过普通调试文字开关，记录模式仍不插入文字。现有 `t` 触摸诊断、菜单与 `z` 重新校准继续可用。

`reason` 为当前采样不计入零偏窗口的原因位：`0x01` 时间/序号无有效进步，`0x02` 加速度模长，`0x04` 角速度或变化过大，`0x08` 重力变化过大，`0x10` 窗口内方向移动，`0x20` 近竖直前臂，`0x40` 角速度截断。`accepted` 和 `generation` 可分别判断采样和姿态更新是否推进；这些诊断是为实机定位提供证据。

## 验证

实际 C 固件回归使用独立的双精度旋转矩阵，生成传感器重力与体坐标角速度，不复制固件四元数实现。运行时间按 100 Hz 前进，校准计数由实际实现维护。

覆盖掌心/手背校准、翻掌前后向上抬臂、600°/秒绕前臂轴翻掌、抬臂后再翻掌时手腕保持位置、重新校准、带启动零偏的采集、5°/秒抬臂不能完成零位采集、近竖直校准拒绝、1° 小倾角初始化、复合 XYZ 运动、线加速度干扰、十轮翻掌抬臂回位、静止温漂估计、2°/秒航向运动、缺口、序号和计时回绕。

所有受检姿态点的最大旋转矩阵元素误差为 **0.002686**（矩阵元素按 ±1 归一化），列向量正交性误差要求低于 0.004；这是本次确定性模拟的数值结果，不是板上角度精度指标。抬臂还检查独立的相机投影公式与屏幕运动方向；45° 时指尖检查在内容区域内。

原有 framebuffer 所有权、缓存清理顺序、分片与全量逐字节一致、1024×600 和 800×480 边界、触摸重复点击/越界/掉线重连、菜单校准、动画和记录模式文字隔离也一并复验。新增预览由校准后的六轴运动驱动导出，非仅手工设置二维倾斜角。

I²C 引脚级 XSim 2025.2 仿真检查量程寄存器、600°/秒原始角速度、正负小角速度、六轴快照、100 Hz、MPU 配置重放与 GT911 按下/松开/再次按下、边缘坐标和重连。于 7.002802130 秒仿真时间正常 `$finish`，有 `TEST_PASS LCD_INPUT`，没有 fatal 或 timeout。

## 使用与实机范围

上电后有效 MPU 数据一到即开始跟随，并显示 `MPU TRACK`。让左前臂朝前、接近水平、掌心朝上，保持静止约一秒完成后台零偏采集，随后显示 `MPU READY`。若正在活动，稳定窗口重新计时，但实时跟随继续。需要重新建立航向时，点击菜单“MPU校准”或在监测串口发送 `z`，再保持静止。实际手背朝上校准也能正常显示，不会被强制改成掌心。用户已确认此前上电实际掌心朝下，因此校准后显示朝下是正常行为。

本次验证是主机模拟、RTL 仿真与本地构建；尚未下载板卡或写入 SD 卡，未实测最终漂移、延迟、帧率、触摸或画面撕裂。MPU6050 没有绝对航向参考，不能保证航向永久不漂；校准时的恒定慢航向转动也无法仅凭这六轴区分成零偏，因此校准必须保持静止。

单个前臂 MPU 测得方向；肘位置、臂长与眼位使用模型约束，没有进行加速度二次积分来推测自由空间位置。手指仍沿用肌电分类的关节模板与插值，不能把它称为逐关节实测重建。

实机验证建议先做“掌心朝上抬臂/放下 → 翻掌 → 再抬臂/放下 → 回到原位”。若继续偏离，保留动作前后 `i` 的全部输出，以区分采样未推进、校准未就绪、角速度截断、采样缺口与残余航向漂移。
