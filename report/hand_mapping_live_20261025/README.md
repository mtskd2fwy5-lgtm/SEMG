# 动作映射实时驱动、上电复位与明亮点击反馈 V10

版本：`20261025_HAND_CONTROL_HDC_DYNAMIC_V10`，2026-10-25。

## 本轮需求与修复

V9 的 `lcd_hand_adjust()` 用 `!hand_view_mode` 将实时驱动限制在逐轴标定页，动作映射只改待保存数值。这是本次“不随映射调节运动”的直接原因，现已补齐两个页面的驱动路径。

- 动作映射中，拖动滑块或点击 ±50/±10 us，同步驱动当前选中的手指；放松/张手/握拳与已学自定义类别共用同一路径。
- 映射页必须先完成六路行程标定；滑块两端对应当前手指已标定的下限与上限，微调也夹紧至此范围。掌部不参与手势映射，继续由 MPU 控制。
- 实时预览只改变输出与编辑值；“记录本轴目标”才保存该轴到当前类别，并撤销该类原有确认。记录时停止预览；仍需“确认五指映射”才允许该类联动。
- 拖动松手、离页、失联、非法触摸坐标、STOP、故障会取消当前轴驱动；微调沿用 1 秒期限。切换类别或轴会先停止旧预览，普通按键按住不连点。
- 点击反馈由 180 ms 缩短到 100 ms，从包含本次反馈的帧提交后计时。填色 RGB(164,245,212)，边框及跳页圆环 RGB(38,204,164)，更亮的薄荷绿；选中状态保持独立。

## 上电自动复位

用户确认目标：**SD 已保存的放松五指映射＋掌部相对 0°**。

触发点是整机程序启动。若只切断再接通舵机电源、FPGA/PS 没有重启，当前没有舵机电源检测输入，不会重新触发此流程。

1. 启动时初始化配置，再调用既有双文件读取与 CRC/代数选择，加载 `HAND0.CFG`、`HAND1.CFG` 中最新的有效配置。
2. 要求完整六路标定、有效的放松映射及每个目标都在已标定范围内。当前测得 500–2500 us 对应 0–270°，相对零点在绝对 45°，掌部复位脉宽约 **833 us**。若此零位不在掌部标定范围内，跳过整次复位，不用夹紧后的另一角度冒充零位。
3. 复位依次为拇指、食指、中指、无名指、小指、掌部，单次驱动每轴约 1 秒；轴与轴之间先 STOP 并等待 ACK。约 6 秒加配置与握手开销。
4. 利用既有单轴 PL 指令与心跳，一次只使能一个 PWM，不改变 RTL，也不伪造 EMG/HDC/MPU 数据绕过自动联动保护。
5. 只在启动入口尝试一次。手动读取配置、切换页面、重新校准、后续识别结果不会重新触发启动复位。
6. 首页显示“机械手复位中”，右上角“停止”可中断。ACK 超时、硬件错误/看门狗故障、页面离开或模式切换会取消后续各轴，不自动重试。
7. 完成后发送 STOP，关闭 PWM，显示“复位指令完成”；**不会自动进入识别联动，也不持续提供六轴保持力矩**。需要联动时再从机械手页面启用。

首次使用需先完成标定，在放松类别逐指记录目标、确认五指映射，然后点击“保存 SD 标定”。仅在 RAM 中记录、未写 SD 的更改无法用于下次上电复位。

这是开环目标指令，不是检测机械原点的闭环回零。普通 PWM 没有实际角度或堵转反馈，无法确认真实到位，也无法根据未知初始物理位置保证首次运动速度；每轴 1 秒是驱动期限，不是实测完成时间。关闭 PWM 也不等同于断开舵机电源。

## 继承与验证

本版固件测试、XSim 回归与 BOOT 验收全部 PASS。复用 PL 的四项硬件验收均通过，WNS +0.441 ns、WHS +0.036 ns；V10 与 V9 镜像内容不同，应用标签与实际加载分区匹配。

继续继承 V9 的滑块标定、公共按钮反馈及 V7 的可追加 HDC。自定义库及新增映射仍在 RAM；未实现中文拼音命名。复用相同已验证 PL bitstream/XSA；仅更改 PS 软件。

- `hand_test.log`：双分辨率下基础/自定义映射实时输出、限制夹紧、零宽范围、显式记录、松手/换类停止；SD 无配置/CRC 损坏回退、最新配置选择、六轴顺序/目标/STOP ACK、毫秒计时回绕、不重复启动、首页停止、ACK 超时、故障边界取消及无效配置拒绝。
- 同一日志的 XSim RTL 自检验证：单轴隔离、同轴目标更新、ACK CDC、MPU 与手势轴分工、HDC 原子目标提交及看门狗保护。没有修改 RTL。
- `lcd_test.log`：800×480、1024×600 的精确 100 ms 到期与回绕、按下/恢复/跳页、实际 RGB 检查、调度/全量逐像素一致、缓冲区保护及原有页面回归。
- `pl_control_test.log`：PS 控制固件、模型/映射一致性、策略、推理、PWM、PL shell 回归。
- `sd_test.log`：标定双文件精确长度、截断/多余内容、读写/同步/关闭错误与录制互斥。
- `boot_build.log`：四项既有 PL 硬件验收、ARM 构建、BOOT 打包及应用/硬件分区一致；`artifacts.json` 记录本版源文件和测试证据 SHA-256。
